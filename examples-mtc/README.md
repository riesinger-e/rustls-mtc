# examples-mtc

Contains example code on using rustls with MTC certs ([RFC draft](https://www.ietf.org/archive/id/draft-ietf-plants-merkle-tree-certs-07.html), v7).

## Structure

- `src/bin/server.rs`: simple TLS server using an MTC
- `src/bin/client.rs`: simple TLS client accepting the MTC used by `server.rs`
- `mtc.json`: JSON file containing a file structure that can be used to issue the MTC's using the [RFC demo](https://github.com/ietf-plants-wg/merkle-tree-certs/tree/7f5561c8f105f40fcb32a420825778eb2964759b).
  - All certificates used in this example were generated using this file: `./demo generate -config ./mtc.json -out ./certs`
- `landmarks.txt`: Landmarks generated by the demo, part of the tools' console output.
- `cosigner.json`: Definition of an extra cosigner for consumption, as defined in `mtc.json` 
- `certs/`: directory containing the generated certificates, see below
- `keys/`: directory containing example private keys

## Run the examples

To run the example code using the generated certificates, you need to add the following entries to your `/etc/hosts`:
```text
127.0.0.1 a.example b.example
```

For both the client and the server, where are several command line options:

### Server

- `--client-auth`: enforce TLS client authentication, off by default
- `--port`: port to listen on, option has a default value.
- `--cert`: path to the certificate, option has a default value. 
  If `--key` is set, this option is required.
- `--key`: path to the X.509 private key, option has a default value. 
  If `--cert` is set, this option is required.
- `--ca`: path to the CA certificate, option has a default value. 
  Only relevant when `--client-auth` is set.
- `--cosigner`: path to a `cosigner.json`. Default is no cosigners (except for the CA).
  Argument may be given multiple times, all given cosigners will be required.
- `--landmarks`: log number, followed by a colon, followed by the path to a `landmarks.txt`. Default is no landmarks.
  Example: `--landmarks 1:./landmarks.txt`

### Client

- `--server-name`: DNS server name to connect to, option has a default value. 
- `--port`: port to listen on, option has a default value.
- `--cert`: path to the client certificate, default value is `None`. 
  If `--key` is set, this option is required.
  When this option is set, TLS client authentication is enabled.
- `--key`: path to the client private key, default value is `None`. 
  If `--cert` is set, this option is required.
  When this option is set, TLS client authentication is enabled.
- `--ca`: path to the CA certificate, option has a default value.
- `--cosigner`: path to a `cosigner.json`. Default is no cosigners (except for the CA).
  Argument may be given multiple times, all given cosigners will be required.
- `--landmarks`: log number, followed by a colon, followed by the path to a `landmarks.txt`. Default is no landmarks.
  Example: `--landmarks 1:./landmarks.txt`

## Keys and generated certificates

The following keys are given in the directory `keys/`:
- `client.pem`: to use with the client (client TLS)
- `server.pem`: to use with server

Both are ML-DSA-44 keys generated using `openssl genpkey -algorithm ML-DSA-44 -out <KEYFILE>`. 
If these keys are changed, the respective entries in `mtc.json` need to be swapped with the output of
`openssl pkey -in <KEYFILE> -pubout -outform DER | base64 -w0`.

The following certificates are given / may be generated from the `mtc.json` into the directory `certs/`:
- `ca_cert.pem`: The CA certificate issuing the MTCs.
- For client authentication:
  - `cert_2012_0.pem` contains a standalone cert signed only by the CA.
  - `cert_2012_1.pem` contains a standalone cert signed by the CA and by the cosigner.
  - `cert_2012_2.pem` contains a landmark cert, unsigned.
- For server authentication:
  - `cert_0_0.pem` contains a standalone cert signed only by the CA.
  - `cert_0_1.pem` contains a standalone cert signed by the CA and by the cosigner.
  - `cert_0_2.pem` contains a landmark cert, unsigned.
